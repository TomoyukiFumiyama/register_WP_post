# Spreadsheet -> WordPress 投稿 Apps Script

このリポジトリには、Google スプレッドシートに紐づける Apps Script (`Code.gs`) を置いています。

## できること

- 1行目に指定ヘッダーを設定
- A列が `入稿待ち` の行だけ処理し、成功した行は A列を `入稿済み` に変更（次回以降は処理しない）
- B列の Google ドキュメントURLから本文とタイトルを取得
- WordPress REST API に投稿（新規/更新）
- C列で投稿先の投稿タイプ（投稿 / 固定ページ / カスタム投稿タイプ）を指定
- 初回投稿時に `WP_POST_ID` を H列に保存し、A列を再び `入稿待ち` にすると同じ投稿を更新として再入稿
- Google ドキュメント本文の記法を、投稿時に装飾HTMLへ自動変換（マーカー / ボックス / FAQ）
- Google ドキュメントの見出し・太字・箇条書きをHTMLとして保持して入稿（ブロックエディタで再利用しやすい形）
- Google ドキュメントに貼り付けた画像を WordPress メディアへ自動アップロードし、本文中に埋め込み

## スクリプト プロパティ

Apps Script エディタの **プロジェクトの設定 → スクリプト プロパティ** に次を設定してください。

- `WP_BASE_URL`（WordPress がルートにある場合はルートドメイン、サブディレクトリにある場合はその格納ディレクトリまで含める。例: `https://example.com` / `https://example.com/wordpress`）
- `WP_USERNAME`
- `WP_APP_PASSWORD`

### 404エラー時の確認ポイント

`WordPress APIエラー: HTTP 404` でHTML（「ページが見つかりませんでした」）が返る場合、`WP_BASE_URL` から組み立てた REST API URL が誤っている可能性が高いです。

- OK例: `https://example.com` / `https://example.com/wordpress`
- NGになりやすい例: 投稿ページURL, `.../wp-json`, `.../wp-json/wp/v2` をそのまま指定

このスクリプトは `WP_BASE_URL` から REST API の到達先を自動判定しますが、判定に失敗する場合は WordPress 側で REST API が無効化されていないか（セキュリティプラグイン・WAF設定など）も確認してください。

補足: `WP_BASE_URL` に `.../wp-admin` や `.../wp-json`、`...?rest_route=...` を入れても自動で補正を試みます。ただし、最も確実なのは WordPress 設置先のURL（例: `https://example.com` / `https://example.com/wordpress`）を指定することです。

## シート列定義

- A: 入稿ステータス
- B: GoogleドキュメントURL
- C: WP_POST_TYPE (`post` / `page` / カスタム投稿タイプのスラッグ。空欄なら `post`)
- D: WP_STATUS (`draft` / `publish` / `pending` など)
- E: WP_SLUG
- F: WP_CATEGORIES (カンマ区切り)
- G: WP_TAGS (カンマ区切り)
- H: WP_POST_ID
- I: WP_POST_URL
- J: 最終実行日時
- K: 最終結果
- L: エラーメッセージ

### C列（WP_POST_TYPE）の指定方法

- 空欄、`post`、`posts` … 通常の「投稿」
- `page` または `固定ページ` … 固定ページ
- カスタム投稿タイプ … スラッグ（例: `news`）、REST APIのベース名、または管理画面での表示名のどれでも指定できます
- カスタム投稿タイプは `show_in_rest` が有効（REST APIで公開）になっている必要があります。見つからない場合は、指定できる値の一覧がエラーメッセージ(L列)に表示されます。
- カテゴリー(F列)・タグ(G列)は、その投稿タイプが対応している場合だけ指定できます（例: 固定ページでは空にしてください）。
- 一度入稿した行の投稿タイプを後から変える場合は、H列の `WP_POST_ID` を空にしてから再入稿してください（別の投稿タイプの投稿として更新はできません）。

### 旧レイアウト（C列が WP_STATUS）からの移行

以前のバージョンでは C列が `WP_STATUS` でした。既存のシートでメニュー `WordPress連携` → `1行目にヘッダーを設定` を実行すると、入力済みのデータを保ったまま C列に `WP_POST_TYPE` 列が挿入され、以降の列が1列ずつ右にずれます。旧レイアウトのまま `入稿待ちを処理` を実行した場合は、誤った列に書き込まないようエラーで停止します。

## 使い方

1. スプレッドシートにこのスクリプトを紐づける。
2. メニュー `WordPress連携` → `1行目にヘッダーを設定` を実行。
3. 必要な行を入力し、A列を `入稿待ち` にする。
4. メニュー `WordPress連携` → `入稿待ちを処理` を実行。終了時に成功・失敗の件数が画面右下に表示されます。
5. 成功した行は A列が `入稿済み` に変わります。失敗した行は `入稿待ち` のまま残り、K列に `失敗`、L列にエラー内容が書き込まれるので、修正して再実行してください。
6. 入稿済みの記事を修正して再入稿したいときは、A列を `入稿待ち` に戻して実行します（H列の `WP_POST_ID` の投稿が更新されます）。

補足: A列にプルダウン（入力規則）を設定している場合は、選択肢に `入稿済み` を追加してください。`入稿済み` に変更できなかった場合も入稿自体は成功として扱い、L列にその旨を書き込みます。

## 処理速度と実行時間について

- `入稿待ち` の行が無いときは WordPress に接続しません。
- 検出した REST API のURLは6時間キャッシュし、毎回のURL判定を省略します（接続先が誤っていると思われるエラーが出た場合はキャッシュを自動で破棄します）。
- カテゴリー・タグは同じ実行内で一度調べた名前を再利用し、検索・作成は並列に行います。
- 画像は並列にアップロードします。ファイル名に画像内容のハッシュ（12桁の英数字）を付け、再入稿時は同じ画像がメディアライブラリにあればアップロードせずに再利用します。
- Apps Script の実行時間上限（6分）で処理が途中で止まらないよう、開始から約4分半を過ぎたら新しい行の処理を止めます。処理済みの行は `入稿済み` になっているので、もう一度 `入稿待ちを処理` を実行すると残りの行から続けて処理します。

## 本文の自動装飾ルール

Google ドキュメント本文に以下の記法を書いておくと、投稿時にHTML装飾へ変換されます。

### 1) マーカー（蛍光ペン風）

- `==強調したい文章==` → `<mark>強調したい文章</mark>`
- `==` と `==` は同じ段落の中に書いてください（段落をまたいだ指定は変換しません）。太字を含んでいても構いません。
- H2ごとに0〜1箇所を目安に使ってください。

### 2) SWELLボックス装飾（アイコン付き）

以下の開始タグ〜終了タグで囲むと、対応するボックスHTMLに変換されます。

- `[POINT] ... [/POINT]` : ポイント・メリット（✅）
- `[CAUTION] ... [/CAUTION]` : 注意点・デメリット（⚠️）
- `[NOTE] ... [/NOTE]` : 補足説明・備考（💡）
- `[SUMMARY] ... [/SUMMARY]` : 要約・まとめ（📝）

書き方のルール:

- 開始タグは段落の先頭、終了タグは段落の末尾に書きます（タグ自体を太字にしても構いません）。
- 1つの段落の中で囲んでも、複数の段落にまたがっても使えます。間にある箇条書き・見出し・画像・太字もそのままボックスの中に入ります。

```
[POINT]
ここに本文を書きます。
・箇条書きもそのまま入ります
[/POINT]
```

```
[NOTE]1段落だけの短い補足です。[/NOTE]
```

- 終了タグが見つからない開始タグは、変換せずにそのまま残ります。
- ボックスの中に別のボックスを入れる（入れ子にする）ことはできません。

### 3) キャプションボックス

- `[CAPTION:タイトル] ... [/CAPTION]`
- タイトル省略時は「補足情報」になります。
- 書き方のルールは SWELL ボックスと同じです。
- 具体例 / 引用 / 参考情報などの補足に使えます。

### 4) FAQブロック

- 「よくある質問」で始まる見出し（Google ドキュメントの「見出し2」など）の後ろにある `Q:` / `A:` を、FAQブロックに変換します。見出しの代わりに `## よくある質問` と書いた段落でも使えます。
- 次の同じレベル以上の見出しまでが FAQ の範囲です。
- `Q:` で始まる段落から `A:` の前までが質問、`A:` で始まる段落から次の `Q:` の前までが回答です。複数の段落にまたがる回答は改行でつながります。
- 全角の `Ｑ：` / `Ａ：` も使えます。
- 例:
  - `Q: 〇〇ですか？`
  - `A: はい、〇〇です。`
- 最初の `Q:` より前の段落と、`A:` が続かない `Q:` は、変換せずにそのまま残ります。
